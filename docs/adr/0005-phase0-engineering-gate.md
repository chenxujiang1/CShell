# ADR-0005：Phase 0 采用可自动验证的工程准入门槛

- 状态：Accepted
- 日期：2026-09-18
- 范围：修订 Phase 0 平台体验与凭据原型的验收边界

## 背景

原 Phase 0 计划把三平台人工读屏、输入法候选窗和视觉判断与系统钥匙串/完整保险库原型并列为准入条件。用户决定先完成可重复的工程验证，在实际使用中持续优化主观桌面体验；完整 Vault 仍属于 Phase 1。

## 决策

1. Phase 0 的 Go/No-Go 以代码检查、协议/平台自动化测试、原生窗口冒烟、安全不变量和既定性能/资源门禁为依据。读屏手感、输入法候选窗观感、Emoji/颜色主观比对和更多真实设备组合保留为明确的后续体验待办，不伪称已经由自动化测试验证。
2. P0-070 验证平台事件与工作台的最小菜单/对话框、IME commit、剪贴板、DPI、AccessKit 语义树等客观路径。完整系统菜单和文件选择工作流随 Phase 1 产品界面建设；P0 不投入完整设置页或皮肤。
3. 新增 P0-075：系统钥匙串最小原型。Windows、Linux、macOS 后端须验证临时 secret 的写入、读取、删除，以及不可用、拒绝和失败后的安全恢复；失败不得损坏已有条目或泄漏 secret。原型不包含主密码、便携加密保险库、配置/凭据 UI、迁移及生产凭据生命周期，这些仍由 P1-080 完成。
4. P0-080 仍须完成 device lost 后的恢复/软件路径及滚动锚点等客观正确性测试。主观视觉精修后移，不免除崩溃、空白窗口、内容丢失或严重输入错误等工程阻断项。
5. P0-099 形成证据矩阵与风险清单。只有客观硬门槛通过才能进入 Phase 1；后移的体验项须被记录，不能写作“已验收”。真实掉电不属于当前验收范围。

## 后果

Phase 0 可以不依赖用户现在提供物理机或进行人工验收；四目标 CI 和可运行的原生测试继续作为工程准入证据。首个面向日常单主机使用的版本仍是 Phase 1 v0.1，多主机同步输入与编排仍是 Phase 2 v0.5。
