# 紧凑 SFTP 传输任务表与显式失败重试

底部传输区使用虚拟滚动任务表，一行一个任务，固定展示选择、文件与方向、状态、进度、速度、剩余时间和操作。文件名、路径、原始错误和已传/总字节可悬停查看。暂停、继续、取消保留为行内操作，失败提供重试，不确定的发布或清理状态提供“核对”并进入原有详细恢复页面。已完成任务可从“更多”清除，仅移除记录。

全部任务默认活动优先、同状态保持原顺序，避免新传输被历史记录遮住。状态筛选包括全部、传输中、等待中、已暂停、已完成、失败、已取消和需核对。全选仅作用于当前筛选，切换筛选清除选择，状态变化移出筛选的任务也从选择中移除。“批量操作”按适用条件显示可操作数量，支持暂停、继续、取消、重试、移除已完成/已取消记录。

批量命令由桌面 IPC 工作线程顺序执行，整个批次持有忙状态，逐项读取最新队列及校验会话身份。不支持该操作或已结束的任务跳过。仅后台明确返回写入前的版本冲突时可刷新后重试；通信中断、存储错误或回执不匹配会停止后续操作，保留已确认结果并要求刷新，避免重放不确定的文件变更。

队列增加可选 `retry_items` 集合和协议 59 的 `QueueRetryMany`。显式重试保留原任务 ID 和日志，原子记录选中任务的重试意图，再由现有并发调度器调度（默认三路）。已知拥有暂存文件的任务按原源文件 SHA-256、目标发布计划、已传前缀与写入边界校验后续传；从未创建暂存文件或已明确清理的任务可重新开始。创建结果不确定、提交中或清理中的任务不自动重试。队列手动暂停时只安排重试，等待继续；重试不会自动解除其他单文件的暂停。旧队列缺少该字段时视为空，空集合不写入 JSON。

取消单个等待任务不暂停其他任务；移除、取消待重试或显式恢复操作相应清除重试意图。调度器允许用户显式重试后继续调度，并在释放运行器所有权后重新检查启动请求，避免收尾与新请求交错时丢失唤醒。

速度使用字节增量平滑估算，暂停、继续、切换传输 ID 或回退进度时重新采样；三秒没有进度则清除过期速率。剩余时间仅在有总量和有效速率时估算，准备、校验、提交及暂停阶段不显示旧估算。任务最多 128 项，表格仅绘制可见行，采样覆盖筛选和滚动范围以外的任务。

GUI 与后台需一起更新。验证包括筛选与批量选择隔离、最新版本提交、不确定回执不重放、手动暂停队列的重试安排、单文件暂停、速度重置、128 项虚拟滚动、小窗口布局、旧记录兼容与异常日志约束，以及隔离运行目录中的真实 SSH/SFTP 排队失败恢复和并发校验续传。

取消期间的校验日志保存将队列锁移交给阻塞写入任务，锁持续到写入真正结束，即使等待它的传输协程已被取消；其他并发文件不会因为后台写入尚未收尾而误报存储不可用。真实队列用例验证了该竞争及并发续传恢复。

暂停显示与批量操作资格以当前传输 ID 的状态为准；显式重试或恢复会清理旧暂停/取消标记，防止同一任务 ID 的新传输继承旧状态。
