# 0134：可选择的跳板连接复用开发方案

日期：2026-11-06。分支：`develop/1.1`。

状态：P1～P4 本地实现与自动化验收完成；P5 的本地自动化及隔离 SSH 联调完成。Windows/Mac 实机操作、真实 PAM 环境、远程 CI 与安装包交付仍须验收，不计为自动通过。

## 目标与现有基础

用户已通过键盘交互登录服务器 A 后，连接经 A 访问的 B 时，可选择复用 A 已认证的 SSH 连接，避免重复输入动态码；同时保留独立连接方式。

当前已完成受管理 B：A 上的 OpenSSH 持有 B 的私钥，B 的终端、SFTP、上传和资源采集共用 B 连接。原实现为 B 重新创建 A 连接；本轮新增弱引用注册表、候选准入及选择入口。

已有 `shared_ssh::TransportLease`、`SshSession::fork_transport`，以及终端渠道复制和 SFTP 复用认证，可作为基础。不能仅把已有 A 的 `Arc<SshConnection>` 塞进当前 `JumpClient`：当前跳板退出会直接断开其客户端，会误断原有 A 及其他依赖者。

## 一、用户行为与默认值

在 B 配置的“代理 / 跳板”页增加“跳板连接方式”：

| 策略 | 行为 |
| --- | --- |
| 优先复用已有连接 | 先查找已认证、身份匹配的 A；没有候选时才新建 A，并按需进行键盘交互认证 |
| 始终新建独立连接 | 不使用连接池，为 B 建立独立 A 连接；不会关闭原有 A |
| 仅使用已有连接 | 没有合格的 A 时直接提示，不新建、不读取 A 凭据、不弹动态码框 |

新建跳板配置建议默认“优先复用”；旧配置缺少策略字段时保持“始终新建”，避免升级后改变连接依赖关系。用户可编辑旧配置启用复用。

连接时允许临时覆盖策略，覆盖只作用于本次连接。选择具体 A 连接时使用运行时连接标识；保存配置只保存 A 的配置引用及策略，不保存运行时连接 ID。

多个候选按实际底层连接去重，显示账号、地址、来源标签、依赖数量等必要信息。多个终端渠道属于同一底层连接时只显示一次。存在多个合格候选时由用户选择，不随机选取。取消选择即取消本次连接。

诊断显示“复用 A 的已认证连接”“没有可复用 A，正在新建连接”等阶段；与既有按需连接诊断入口整合。

## 二、首版范围

- 先覆盖一层普通 A 跳板，支持 A 的键盘交互、密码、私钥等既有认证方式。
- 同时接入普通跳板 B 和“由 A 上的 OpenSSH 认证 B”两种模式。普通跳板需要 A 允许 direct-tcpip；受管理 B 使用 A 的 exec/PTY，不额外要求 TCP 转发。
- 覆盖 B 终端新建、独立 SFTP 新建。由 B 终端打开 SFTP 仍优先复用 B 本身，避免为同一 B 再创建 ControlMaster。
- A 上手工执行 `ssh B` 不改变 A 底层连接的身份；复用通道与该终端的输入、目录及输出独立。
- 现有多级跳板保留独立连接行为。首版不增加多级跳板复用，也不允许受管理 B 继续作为下一跳；不支持的复用组合在配置/连接前明确拒绝。
- 两台远程服务器互传仍是后续 NF-04；本次只为它提供统一的连接基础，不计为已实现互传。
- 受管理 B 的 Linux A/B、A 端信任 B、手动重连等现有限制保留；资源面板默认一次采集、间隔 0。

## 三、身份与候选准入

新增 daemon 内部跳板连接注册表，注册已完成认证、可使用的普通 SSH transport。只在同一后台实例、同一用户和数据目录范围内复用，不接管系统 ssh 或其他程序的连接。

候选至少包含：不透明 transport ID、连接代次、A 配置 ID、建立时冻结的连接相关配置、实际认证用户名、主机指纹、完整已验证路线、后端能力和运行状态。

匹配条件包括：

1. A 配置 ID 及连接相关配置一致；账号、主机/端口、代理或路线、认证引用等不能被当前配置悄悄替换。
2. 使用实际认证用户名，不把空用户名当作任意账号匹配；地址相同但账号或配置不同不复用。
3. 实际主机身份与当前信任要求一致；信任记录变化、撤销、证书失效或不能重新判定时，拒绝新增复用，不以“已经连接过”绕过信任策略。
4. transport 仍就绪，未进入关闭或重连状态；代次与查询时一致，具备所需能力且租约额度可用。

注册表仅持有弱引用和必要元数据，不缓存密码、动态码、私钥正文，也不使无人使用的连接永久存活。连接元数据不写入配置或监控历史；已有日志仍遵守脱敏规则。

GUI 候选查询不读取秘密、不解锁凭据库。候选选择使用短时、与创建请求和目标配置绑定的令牌；查询结果不是执行授权，后台获取租约时必须再次核对身份、配置、信任和代次。

## 四、连接流程及失败语义

执行顺序：读取并冻结 B/A 配置 → 解析策略与候选 → 原子取得 A 租约或决定新建 A → 仅准备尚需认证端点的凭据 → 建立 B → 验证 B 并等待终端就绪 → 提交会话。

必须将当前在创建入口提前执行的 `prepare_plan` 拆分为“计划选择”和“实际新建认证端点准备”。仅取得 A 已有租约、B 又由 A 认证时，不读取本机 A/B 的认证秘密，也不为此要求解锁凭据库。普通 B 如仍需本机认证，只准备 B 的实际凭据。

保留 daemon 所有权、认证取消代次和 `commit_auth` 提交守卫；创建期间锁库、修改认证上下文或取消操作，仍按现有规则取消并清理。本功能不把锁库转化为强制断开既有连接，也不借复用绕过新凭据读取的限制。

回退规则：

- “优先复用”仅在尚未选定/取得 A 时、没有合格候选的情况下新建；界面先明确新建认证阶段。
- 用户明确选择的 A 失效时提示重新选择或新建，不悄悄切换到另一个候选。
- 已取得租约后，B 认证失败、主机指纹异常、A 通道被拒绝或超时，不自动换新 A 再试；避免重复验证码、重复 B 连接与误绕过资源限制。
- “仅使用已有连接”任何失败均不触发新建 A；服务端通道上限也不能通过静默新建来绕过。
- 连接结果不明不自动重发，不重放终端输入、上传或动态码。

并发“优先复用”且 A 尚未连接时，按 A 身份串行协调首次认证：后续请求可取消地等待，再重新查询已就绪连接，避免同时弹多个动态码框。只复用已经认证完成的连接；不把半认证连接暴露为候选。等待者取消只移除自己；认证发起者取消后不把其迟到结果提交为成功，其他请求再按自身状态决定继续或提示。“始终新建”保持各自独立。

## 五、租约与生命周期

重构跳板持有方式，区分自有连接和借用租约，最终统一到能够独立释放的 transport lease。借用必须创建独立消费者，不能只 clone 同一消费者句柄。

- 原 A 终端持有自己的租约和 writer；B 持有 A 的另一个租约，不持有 A 终端 writer。
- B 继续拥有自己的 ControlMaster、终端、SFTP 和监控状态；取得 A 租约不意味着不同 B 共用一个 B 主连接。
- 关闭 B：先终止其 B 通道并清理自己的 A 端运行目录，再释放 A 租约；不直接 disconnect 借来的 A。
- 关闭 A 终端标签：只关闭该 shell 并释放其租约；B/SFTP 等消费者仍在时保留 A 底层传输。A 终端已有远端运行程序仍按现有关闭语义处理。
- 最后一个消费者离开后关闭 A；注册表弱引用不能阻止清理。
- 关闭单个标签只释放其消费者；首版不增加强制断开整个共享传输的入口。将来提供该入口时，必须先显示受影响的 B/文件会话。依赖关系只保存 ID，避免强引用环。
- A 掉线时，旧代次上所有 B 进入明确的断开/失败状态；A 自动恢复的新连接不能透明接管旧 B，B 仍由用户手动重连，不回放操作。
- B 初始化失败、取消或超时，只清理自己创建的远端运行资源和租约，原 A 及其他 B 继续工作。

延续每连接最多 64 个消费者的现有限制；这不等于服务器允许 64 个 SSH 通道。新增通道并发/预留约束需与现有预算统一，真实服务器 `MaxSessions` 更低时清楚报错。锁内只做状态校验和引用调整，网络操作放在锁外；租约获取和最后释放需保证不能“关闭后再复活”。

## 八、必须覆盖的验收

| 场景 | 预期证据 |
| --- | --- |
| 已登录 MFA A，再连接受管理 B | A 新增 TCP/认证/挑战次数均为 0；B 正常连接，私钥留 A |
| 已登录 A，选择始终新建 | A 新增独立连接并完成服务端要求的认证；关闭任一独立连接不影响另一条 |
| 无 A，优先复用 | 明确进入 A 新建认证，再连 B；不假报复用 |
| 无 A，仅复用 | 新增 TCP/认证/凭据秘密读取均为 0，明确报无候选 |
| 多个 A / 同 IP 不同账号 | 按实际 transport 去重，用户选择，错误账号/配置/路线不进入候选 |
| 查询后关闭、重连或修改配置/信任 | 旧令牌/代次拒绝；不连接错误 A，不静默换候选 |
| 原 A 被锁库但连接仍有效 | 全复用场景不重复解锁；创建中锁库/取消仍按提交守卫拒绝，既有会话不被误断 |
| B 失败或取消，A 上还有操作/其他 B | A 仍可输入、输出；已有 B/SFTP 不受误清理影响；新建资源释放 |
| 关闭 A 标签 / 关闭 B / 最后消费者离开 | 依赖者存续正确；无提前断开、无强引用环、无无人持有的残留连接 |
| 共享 A 网络断开及恢复 | 全部依赖者显示旧连接失效；B 不自动迁移、不重放输入或上传 |
| 并发连接与独立取消 | PreferExisting 同身份首次认证不同时弹多个 MFA；取消者无迟到提交，无泄漏 |
| A 通道上限、拒绝 exec/PTY/转发 | 报准确能力/资源错误，不用新认证隐藏失败，不影响原 A |
| B 终端、SFTP、拖放、监控 | 实际文件和采集命令到 B，目录身份与指纹检查保留；监控默认一次、间隔 0 |
| 协议与数据兼容 | 旧配置不改变行为，策略持久化和导出可核对，旧后台/未知枚举明确拒绝 |

真实测试使用隔离 MFA SSH 服务记录 TCP、认证和挑战次数；仅“没弹窗”不足以证明复用。同时覆盖 A 禁止 direct-tcpip 的受管理 B 场景和允许转发的普通 B 场景。现有终端复制渠道、独立 SFTP、凭据库路由、指纹变化及资源面板均纳入回归。

开发检查复用默认 target 和固定日志；不新建多套试用产物、不覆盖运行中的程序。通过代码检查和本地联调后，还须完成 Windows/Mac 客户端实测：重复连接、多个窗口、取消动态码、关闭标签、睡眠/切网及恢复。规划文档本身不声称这些已完成。

## P1、P2 阶段验收记录（历史）

以下记录保留阶段验收时的边界；P3/P4 已在后续实现中接入，当前行为见下节及使用说明。

- 当前 IPC minor 80。三态策略进入现有 options JSON；旧值缺省 AlwaysNew 并省略写出。新增连接推荐值 PreferExisting 已在领域接口定义，正式 GUI 新配置默认值随 P4 入口接入，当前界面不会提前启用尚不可执行的策略。
- 非默认策略的 SSH 配置使用专用 wire 路线 kind 4，并要求策略标记一致；旧解码器拒绝未知路线，不会读取后无声丢弃 OnlyExisting。普通 CShell JSON 保留策略；普通 OpenSSH 导出拒绝无法表达的非默认策略。
- 终端 SessionCreateRequest 和独立 SFTP 请求均提供单次覆盖字段。候选 ID、代次及短时令牌属于请求，不存入配置。终端复制渠道/本地终端与跳板覆盖互斥，目标 SFTP 渠道复用与跳板覆盖也互斥。
- 候选协议现阶段返回 Unsupported 和 execution_supported=false，不把空候选列表解释成可执行。非默认策略或具体候选在任何新建 A 认证前拒绝；本次显式覆盖为 AlwaysNew 时只改变执行计划，不改写保存的配置。未知策略、无效候选和不支持的路线明确拒绝。
- 跳板链改用独立 TransportLease。释放借用租约不直接断开共享 A；最后一个消费者才清理该底层连接。清理任务独立于等待者存活，取消等待不会取消实际清理；并发/重复释放等待同一结果。release_confirmed 表示当前引用已释放且所需清理已确认，不表示仍有其他消费者的 A 被关闭。
- 真实 SSH 租约测试通过手动传入已有 A 引用验证 P2 生命周期，不代表 P3 的自动候选查找已完成。固定验收报告：artifacts/ui-refresh-20261015/logs/ssh-audit-jump-reuse-p1p2.md。

## P3、P4 当前实现

- 当前 IPC minor 81。候选查询和创建均进入 daemon 弱引用注册表；实际账号、冻结配置、当前主机信任、证书有效期、代次、60 秒单次令牌重新校验后取得独立租约。
- 凭据准备位于准入之后，复用 A 时只准备 B 仍需的本机凭据。首次并发优先复用按 A 配置协调认证；已就绪 A 的 B 初始化并发上限为 2，消费者上限保持 64。主动锁库和取消不产生迟到提交。
- 终端与独立 SFTP 共用三态策略和候选选择界面；多个候选明确选择，失效不自动改用另一条。保存配置与临时覆盖分别生效；旧配置沿用独立连接，新建跳板默认优先复用。
- 普通 B 使用 A 的 direct-tcpip；受管理 B 使用 A 上的 OpenSSH，密钥留在 A。原 A 标签关闭后，其他消费者继续持有底层连接；目标需手动重连，不自动迁移或重放操作。
- 批量任务等旧连接入口仍拒绝非默认复用策略，不将其降级为独立连接。Windows/Mac 真实交互与安装包验收不由单元测试代替。
