# ADR-0019: Explicit synchronized input control

- Status: Accepted
- Date: 2026-10-01

## Phase 2 contract

P2-010 and P2-020 use an ephemeral synchronized-input controller in the application layer. Its port exposes only already opened interactive tabs and submits logical `InputAction` values to each target's independent bounded queue. The port must atomically recheck both source and destination session identity and input eligibility immediately before enqueueing, and must never wait for a remote writer. Check the source first regardless of selection order. A source transition stops further enqueueing and disarms; already queued inputs retain their actual outcomes. Existing local/SSH handles encode against their own terminal modes. Raw bytes from the source terminal are not broadcast.

An arm review freezes tab/session identities, kinds and display labels. Arming requires explicit approval, rechecks identities and eligibility, rejects duplicate tabs or sessions, and never adds newly opened tabs. Local targets require individual manual selection; mixed SSH/local groups are rejected. The limit is 256 targets, matching the current workspace tab limit; groups above 10 targets require a separate confirmation when arming. The frozen target list remains available for the fixed warning bar and target borders. Disarm invalidates outstanding reviews and inputs. A new controller always starts disarmed; armed state is not serializable.

Only committed terminal input from an armed source tab may prepare a broadcast. IME preedit, application shortcuts, secure input and locked input are refused. Secure or unavailable source state blocks the whole operation; individual unavailable or changed destination sessions receive explicit delivery failures. The port treats unknown security state as ineligible. Authentication forms and manually marked secure terminal input must never enter this broadcast path. Raw PTY output does not reliably identify password prompts; this controller does not claim otherwise.

Prepared inputs own their exact action, frozen target snapshot and confirmation reasons, expire after 30 seconds, are not cloneable, and are consumed once. Multiline/control-bearing text or paste and suspicious destructive commands require confirmation. This classifier is a conservative prompt for recognizable commands, not a proof that shell text is safe. GUI Compose and paste review must show the actual frozen targets and exact text before granting approval. Logical Enter/control/function keys remain supported without pretending that the controller knows the remote shell's current command line. The action limit is 1 MiB, matching single-target IPC. Prepared payloads redact Debug and clear their text on drop; audit records contain identifiers, input kind/byte count, target identities and enqueue statuses only.

An audit sink must accept arm/send metadata before state becomes armed or any input is enqueued. Audit failure before dispatch sends nothing. Failure to record the final delivery metadata cannot undo queued input: report the real enqueue results, mark the audit incomplete and disarm. Delivery means queue acceptance only, with no remote execution, exit-code, retry, idempotency or consistency claim.

## Implementation and acceptance

The application controller is connected to the desktop selection/review/Arm/Disarm workflow, fixed warning bar, target borders, secure-input switch and Ctrl+Shift+Escape exit. Windows share one live controller. Hidden selected targets attach only their existing runtime sessions. Keyboard, IME commit and paste route logical actions; broadcast keyboard routing preserves releases and character information independently of the source modes. Authentication configuration UI is excluded. Focus loss, source changes and close revoke pending reviews and inputs.

Production queues stamp each action with the expected SessionId and a fresh connection epoch. Session switching, reconnecting, closing and security transitions invalidate old epochs. Synchronized enqueue atomically checks source and destination using stable lock order; worker dequeue checks identity/security again before starting its IPC write. Weak arm permits and audit-health guards revoke writes that have not started. A write already started cannot be recalled; no rollback of remote input is implied. Each target has its own bounded, nonblocking queue: at most 256 queued items and a combined 4 MiB budget for queued/in-flight text plus fixed action overhead. Reservations are refunded on completion, discard or enqueue rejection. Worker/daemon rejections are surfaced separately from enqueue receipts.

The desktop metadata audit sink creates a unique JSONL file in an owner-protected runtime directory. A bounded 256-record queue accepts metadata without waiting for disk; a background worker writes and syncs each record. Acceptance is not a durability acknowledgment and a process crash can lose queued metadata. Writer failure or the 64 MiB per-attachment cap fails closed and revokes pending synchronized writes. Payloads, key values, terminal output, titles and payload hashes never enter these records. Final audit rejection must still report true enqueue outcomes and incomplete auditing.

Automated gates cover the actual desktop adapters, owned local PTYs with authenticated IPC, target-specific production encoding and Headless UI state. They do not establish native GUI interaction, platform IME behavior, external SSH or four-platform acceptance. P2-010/020/099 and the remaining P1 platform/manual gates stay open until their acceptance matrices are fulfilled.
