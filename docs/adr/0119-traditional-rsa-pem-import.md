# 0119：传统 RSA PEM 私钥导入兼容

导入密钥只根据文件内容识别格式，不依赖文件后缀。原实现将传统 `BEGIN RSA PRIVATE KEY` 文件交给禁用了上游 RSA 实现的解码器，导致正确口令也失败；其传统 PEM 解密分支也未覆盖 DES-EDE3-CBC。界面随后给出笼统的格式或口令错误。

新增有界的传统 PKCS#1 PEM 读取路径，兼容未加密文件，以及 DES-EDE3-CBC、AES-128/192/256-CBC 文件。历史 PEM 使用的 MD5 EVP_BytesToKey 仅用于读取旧文件，CBC 解密交由 ssh-cipher 实现，DER 结构交由 der 解析。要求完整单一 PEM、准确 IV 长度、有效填充、双素数 RSA 参数与 CRT 一致性，并复用 ring 公私钥校验和 RSA 2048–4096 位限制。文件上限 64 KiB，口令上限 4096 字节，传统解析并发上限为 2。

导入和直接 SSH 私钥读取统一移除文本 BOM、规范换行；口令不裁剪、不改变 Unicode 或空格。导入前仍限制 OpenSSH KDF 成本。解密缓冲、派生密钥、规范化私钥文本及 CRT 临时量使用 zeroize。错误信息只包含固定类别，不回显文件内容或口令。

导入后沿用原有 OpenSSH 编码和凭据库加密流程，保留原私钥口令；原文件不修改。此次兼容不启用 SSH 传输中的 3DES，也不启用 RSA/SHA-1 登录或上游 RSA 后端，现有 ring RSA/SHA-2 签名策略不变。IPC 和凭据库格式不变。

导入错误区分公钥误选、缺少私钥口令、解密失败或加密数据损坏、不支持的算法、格式不完整、参数超限与一致性失败。无认证标签的历史 CBC 文件无法可靠区分错误口令和密文损坏，因此不把所有解密失败断言为密码错误。每次新建导入表单清空前次文件路径，避免沿用不相关公钥。

回归夹具由 Windows OpenSSH 和 .NET 加密实现独立生成，是专用废弃测试密钥；覆盖无后缀的 3DES 和 AES-128 PEM、正确/错误/缺少口令、BOM/CRLF、不支持的文件加密、截断文件、公钥误选、保留口令首尾空格与 Unicode，以及中文路径下的凭据库导入和加密 OpenSSH 导出。未读取或使用用户的私钥或密码。
