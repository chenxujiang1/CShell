# 0100 — SSH 保活与有限次数的断线恢复

SSH 配置编辑器增加“连接选项”页。新建配置默认启用 SSH 保活和自动重连：空闲 15 秒发送一次 SSH 协议保活，连续 3 次无响应后断线；意外断线后每隔 5 秒重试，最多 3 次。间隔和次数可分别调整，也可单独关闭两个功能。设置保存后对新连接生效。

选项属于非秘密连接数据，经过领域校验、protobuf 传输和 SQLite 持久化。数据库 schema 16 以事务为旧 SSH 表增加 `options_json`；旧记录和旧 JSON 缺失选项时保留原先保活 15 秒、3 次无响应、不开启自动重连的行为。导入来源没有相应设置时也使用兼容默认值。

保活直接配置 SSH provider，不发送终端字符；目标和每个跳板使用各自的设置。自动重连由后台 SSH 会话监督，保持原会话 ID、标签、终端管道和历史记录。每次恢复重新读取凭据，重新校验目标与跳板密钥，并固定首次连接时的主机身份；认证、凭据或信任错误立即停止，只有网络错误继续消耗重试预算。

远端返回退出状态或退出信号、终端存储失败、用户手动断开和关闭标签均停止恢复。等待、认证和提交阶段都可被关闭操作取消，凭据库锁定也会取消恢复。重连打开新的远端 shell，不恢复远端进程。传输切换前清理待处理的协议响应并重置终端模式；输入命令携带连接代际，旧连接排队输入不会送到新 shell。

频繁断开后短暂连通不会清空重试计数；连续连接稳定 30 秒后才恢复下一轮完整预算，避免反复重开 shell。

GUI 输入还携带排队时可见的快照代际。后台在终端重置完成后设定新 shell 的输入下限，拒绝仍指向旧快照的延迟 IPC 输入；即使 GUI 状态轮询未观察到中间断线，也不会把旧队列送进新 shell。

会话列表提供明确的 `reconnecting` 状态，GUI 为当前和后台标签显示重连状态及重试进度；等待重连时仍能使用“断开”停止该会话。新的 SFTP 和隧道请求读取当前传输句柄，原连接上失败的操作不会自动重放。

验证包含实际本机 SSH 服务器的意外断线恢复、同一会话内新 shell 的输入、正常退出不重连、手动取消、网络重试耗尽和主机密钥变化停止；另有保活协议配置、IPC 往返、旧数据兼容、数据库迁移和设置页点击保存/重载测试。
