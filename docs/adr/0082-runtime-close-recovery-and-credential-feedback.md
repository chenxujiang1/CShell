# ADR-0082：会话恢复与凭据操作反馈

- 日期：2026-10-15

## 修复

连接或握手超时发生在发送会话动作前，重试保留原动作；不会退回默认本地
终端或原会话。关闭失败后，只重新附着未被关闭操作针对的当前进程，不重发
终止请求，也不创建进程。

运行时视图恢复与布局选择分离。终止成功先更新已打开会话列表，再清理标签；
即使 autosave paused，也能恢复原有终端或为保存的占位标签启动只读列表连接，
不修改保存的布局。

保存配置及凭据变更共用一个同步准入状态：请求提交即进入等待，直到后台
完成才释放；队列不可用时显式报错。凭据处理期间禁用连接编辑区，保存、
移除密码成功后显示中文结果。防止连续点击向后台堆积密码操作。

## 崩溃排查

用户报告“输入密码、保存、反复移除后退出”。本次检查现有试用 stdout/stderr、
Windows Application 事件、WER 归档和 CrashDumps，未找到对应本次操作的
崩溃记录。历史记录时间更早，不能据此归因本次退出。

新增 Rust panic 诊断，固定覆盖 logs/gui-crash.log（启动器设置 CSHELL_LOG_DIR；
无该变量时使用 runtime 或临时目录）。只写版本、时间、进程、源码位置和
栈，不写 panic payload、密码或应用状态。此钩子不捕获原生访问异常或强制结束。

## 验证

- 模拟一次握手不回复，再恢复连接：首个控制请求仍为原 Profile 创建请求。
- 隔离真实终端：无效会话移除失败后当前终端恢复可输入；真实 paused 状态
  下终止成功，已保存布局不变、会话列表立即更新并继续刷新。
- 完整 egui 密码输入、保存、移除循环；等待期间连续点击不再产生操作，
  完成提示确实进入绘制内容。后台额外验证 200 次重复请求只入队一次。
- 子进程触发 panic：保存源码位置与栈，报告不含模拟密码。
