# 0133：由 A 上的 OpenSSH 认证受管理 B 会话

日期：2026-11-06。开发分支：`develop/1.1`。本功能尚未发布。

## 使用方式

1. 先保存并验证服务器 A 的普通 SSH 配置。
2. 新建服务器 B 的 SSH 配置，填写 B 的地址、端口和用户名。地址可以是 A 上的 SSH 别名，但端口与用户名以此处填写为准。
3. 在“账号与认证”勾选“由跳板服务器的 OpenSSH 认证目标服务器”。可填写 **A 上**的私钥绝对路径；留空使用 A 上的 OpenSSH 配置与可用 Agent。
4. 在“代理 / 跳板”选择 A，保存并连接 B。
5. 使用这个 B 标签的终端、拖放上传、SFTP 和“查看 → 服务器资源…”。三者绑定同一个 B 目标，不再需要在 A 终端里手工输入 `ssh B`。

首版验证范围为 Linux A/B 和 A 上现代 OpenSSH。A 必须允许非 PTY exec 和终端 PTY；B 需要可用的 POSIX shell、SFTP，资源采集需要标准 Linux `/proc`。只有交互 shell 内才可访问的 Agent 环境不一定能被新会话继承，需先保证 A 的非交互 SSH 能免密连接 B。不会从本机查找 B 的密码或私钥，也不会把 A 的私钥复制到本机。

B 的指纹由 **A 上的 OpenSSH 与其 known_hosts** 校验。本模式不自动写入或更新 A 的信任记录；未知或变化的指纹有明确提示，须先在 A 核实。CShell 记录 A 回报的 B 指纹，后续固定身份重连仍需匹配；这不等同于本机直接执行 B 的 SSH 密码学握手。

## 上传目录误用修复

终端输出是普通程序都能产生的数据，嵌套 SSH 的 B 可以把 OSC 7 目录上报传回 A 标签。此前仅提取 URI 路径，可能拿 B 的目录去访问 A 上的同名路径。

现在拖放上传必须从标签绑定的 SSH 端点，经过独立只读命令取得标记 shell 的目录及实际主机名。OSC 7 仅作为需要核对的附加声明，不直接授权上传路径：主机声明或路径不一致时停止，无法获得可信目录时也停止；不回退到家目录或另一台服务器。用户可在 SFTP 明确选择目录。

目录证明取实际 `/proc/<shell>/cwd`，OSC 逻辑路径和该物理路径不一致（例如某些符号链接工作目录）、主机别名无法核对或不支持该 Linux 查询时，自动拖放可能拒绝，此时使用 SFTP 明确选择目录。此处优先避免传错位置。

拖入时的提示明确说明：上传指向此标签绑定的服务器，终端中再次手工 SSH 不会切换上传目标。受管理 B 会话内再手工 SSH 到 C，也不会自动把文件和监控目标改成 C。

## 连接与通道

- 为 B 创建专用 A SSH 传输，不向用户原有 A 终端注入登录命令。
- A 使用 OpenSSH ControlMaster 建立 B 连接，终端、SFTP、校验、目录探测和监控复用它。无需为每次采集重新认证 B。
- 主连接启动按认证成功、指纹和复用监听器就绪判断，不等待持久进程退出。控制通道由后台异步接收并丢弃后续诊断；不写远端诊断文件或终端历史。
- B 的交互终端另有随机就绪标记。收到 B 标记后才开放会话输入，去掉标记并保留其前后的真实输出，避免 A 只接受了 exec 就误认为 B 终端就绪。
- 文件在本机与 B 的 SFTP 之间流式传输；A 不保存用户文件副本。B 上正常的传输临时文件和最终文件仍遵循原上传策略。
- 所有复用子请求设置 `ProxyCommand=false`：复用主连接消失时失败，不静默新建另一条 B 连接，不回退到 A。
- B 的保活设置映射到 A 上 OpenSSH 的 ServerAlive 参数。首版要求手动重连，界面禁用本模式的自动重连；不自动重放输入、命令或上传。
- 首版仅提供 PTY、Exec、SFTP；继续作为下一跳和 GUI 隧道等能力拒绝执行，绝不把不支持的 B 操作发到 A。

## 服务端影响与清理

A 上会有 OpenSSH 连接进程及 `/tmp/cshell-hop.<随机值>` 私有目录和控制套接字，权限受 `umask 077` 限制。这是连接运行数据，不是监控历史；不安装常驻 Agent，不修改用户 SSH 配置。正常退出关闭 B 主连接并只尝试移除自己的空目录，不递归删除文件。异常断开无法及时清理时，控制主连接采用 60 秒空闲退出，可能留下少量临时目录；不会删除来源不明的目录。

资源面板仍默认只采集一次、刷新间隔 `0`；用户主动启用自动刷新后才周期读取 B 的基础指标。监控不写本机或远端历史文件。服务器自身 SSH 审计由其系统配置决定。

## 配置兼容与执行边界

新增默认 false 的 `authentication_on_jump`，false 时不进入 JSON，不改变旧配置的序列化形状；使用原有 options 存储，不重写用户数据库或凭据。模式启用后本机认证步骤为空，凭据库准备只检查 A 等实际认证跳板。

受管理 B 最初引入于 IPC minor 79；跳板复用配置协议为 minor 80，候选准入与执行为 minor 81，具体边界见 ADR 0134。受管理模式仍同时使用专用认证枚举 `ManagedByJump = 4` 和选项标记，两者必须一致。旧客户端不能把未知新模式静默降级成普通本机认证；GUI 和 daemon 应成套更新。原生 1.0 配置默认不启用；创建本模式配置后，不要用不支持它的旧程序编辑该数据，回退使用兼容备份。

CShell JSON 配置导入/导出保留此模式。普通本机 OpenSSH 配置导出明确拒绝本模式，避免误导成“本机私钥认证的 ProxyJump”。
