# SFTP 初始目录与上传后校验进度

独立 SFTP 用子系统的 REALPATH . 取得远端账号的初始目录，不猜测 /home/用户名，也不再固定进入 /。从当前 SSH 打开时优先该 Shell 报告的 OSC 7 路径；未报告时，通过独立非 PTY exec 渠道进行有界的 Linux /proc 只读查询。没有往终端注入 pwd、按键、命令或修改 Shell 启动配置。

新 PTY 发送不要求回复的 LC_CSHELL_SESSION 渠道标识，服务器可按 AcceptEnv 策略忽略。Linux 查询以完整环境记录精确匹配此标识，避免多个 Shell 互相串目录。不接受标识时，可按当前 exec 的 SSH_CONNECTION 精确匹配同一网络连接，并且只在全部候选进程属于同一个 SSH_TTY 时使用；有歧义不猜测。探测最多 4 秒、输出上限 8192 字节，渠道关闭不关闭共享连接。无法探测、非 Linux、受限账号或目录在 SFTP 命名空间不可用时回退到子系统初始目录。

OSC 7 支持跨包、BEL / ST、百分号 UTF-8 解码，上限 8192 字节，拒绝非绝对路径、控制字符和非法路径；网络重连时清空旧目录。SFTP 初始化只选择一次目录，后续载入保留用户已导航的位置。

上传后旧实现执行完整源复核、临时文件 SHA-256、发布以及临时 / 目标文件的全量复核。新文件正常路径会有三次远端读回：发布前一次，发布后两个路径各一次。因此进度达到上传 100% 并不代表所有完整性检查结束，旧 UI 把后两次检查统称“提交中”使耗时难以判断。

保留全部 SHA-256 与恢复 / 清理保护，将发布后的两个只读检查使用有界并行读取流水线，同时等待两个检查完成和关闭句柄后才处理失败。每个检查仍按既有 1 MiB 批次、16 个请求上限运行。三个并发上传的校验缓冲上限按两个检查 × 1 MiB × 3 个任务计算；不把整个文件载入内存。并行优化减少串行等候，完整读回仍有网络和磁盘成本，不承诺消除该成本。

IPC minor 64 增加运行时传输阶段、阶段字节数与总量；不改变持久化队列格式。界面区分准备、传输、校验文件、发布文件、核验目标、清理，校验进度展示当前阶段完成度，传输速度和剩余上传时间不用于代表校验速度。阶段回调只更新内存状态，不新增每块磁盘日志。

验证覆盖真实本机 MFA SSH 的两个独立渠道目录、独立 SFTP 主页、目录观察器预算、POSIX Shell 模拟 /proc 的四种匹配条件、真实 SFTP 协议全量校验进度与句柄关闭，以及任务表校验阶段的可视进度。Windows 上的 /proc 选择逻辑由真实 sh 加模拟进程文件验证；未连接用户的 Linux 服务器。

目录发现通过 ConnectProfile 的可选 discover_directory 请求字段显式选择，默认 false。旧版 UUID / 对象请求保持旧回复形状，不发送 initial_directory，以兼容 deny_unknown_fields 的旧客户端；新版 GUI 仅在 minor 64 以上发送目录发现请求。传输进度是 protobuf 的可选新增字段，旧客户端可忽略。
