# 终端显示层次、宽字符光标与历史缓存

日期：2026-11-12。分支：`develop/1.1`。本地验证结果见固定报告 `artifacts/ui-refresh-20261015/logs/display-audit-verification.md`。

## 已复现的问题

1. 终端逐格交替绘制背景与字形，双宽字符的右半边会被下一占位格的底色、反色或选区盖住。修复前真实 GPU 读回确认，带不透明底色的“中”字右半边笔画像素消失。
2. 块状光标对默认透明背景一律使用黑色文字，导致浅色主题的光标内字符对比度只有约 1.45。改为使用主题的实际背景色作为光标内文字颜色，保留显式单元格背景语义。
3. 块状、下划线和空心光标只覆盖一个格，中文占两个格。现在从双宽占位格归一到字符起始格，并覆盖两格；竖线光标保持竖线形状，隐藏光标继续隐藏。
4. 历史几何缓存只比较 source ID、revision、布局与视口参数；这些编号并不是跨会话唯一的。切换到相同编号、不同内容的历史页面时可能留下旧画面。缓存现在同时持有并校验页面 Arc 身份，和终端快照一样；持有 Arc 避免内存地址回收后被复用。

## 绘制与资源边界

终端按“全部单元格背景／搜索／选区 → 块状光标背景 → 全部字形／下划线 → 光标轮廓”绘制。历史视图同样先绘制背景再绘制文字，保护中文和斜体越过单元格边界的笔画。各分屏仍保留独立的 scissor 和字体图集帧内固定策略。

额外顶点暂存只覆盖可见区域及 overscan，不采集远程数据、不扩展终端历史、不保存用户终端输出。历史缓存只保留当前一个几何来源，不累计保留不同会话的页面。未改变 IPC、存储格式、字号设置或 SSH 输入行为。

## 验证

新增回归覆盖不透明背景／反色／选区中的中文、浅色主题光标对比度、双宽光标起始格和占位格、历史背景顺序及不同会话的相同历史编号。GPU 回归使用真实渲染管线读取像素，比对无底色和带底色中文右半边的笔画掩码；本地验证显式要求 GPU，未把无适配器跳过当作通过。

本轮完整渲染测试、桌面交互测试、终端／IPC 回归合计 542 项通过，格式和全工作区严格 Clippy 通过；几何性能基准与 Windows 优化构建完成。隔离的原生多窗口门禁也通过：120 次呈现、10 个历史页面、13 次重排、5/5 次窗口尺寸变化、一次设备丢失后的软件渲染恢复、第二窗口呈现及五次字号更新。未向用户正在运行的窗口注入按键，未操作其服务器和会话。Mac 实机、跨显示器 DPI 操作和远程 CI 不属于本轮已执行验证。
