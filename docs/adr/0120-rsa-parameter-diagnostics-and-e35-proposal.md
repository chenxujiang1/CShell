# 0120：RSA 参数诊断及 e=35 兼容提案

用户后续明确选择不兼容 e=35；下面的兼容提案已取消，不实施签名后端或准入变更。保留已完成的诊断修复与回归验证。

## 已确认的原因

用户明确授权检查的公钥显示 RSA 模数为 4096 位、公有指数为 35。传统 PEM 的 Proc-Type、DEK-Info 和 8 字节 3DES IV 不参与 RSA 位数计算。DER 的正数符号字节也已由 UintRef / Mpint 剥离，不是此次失败原因。

当前 ring 私钥签名器要求奇数公有指数在 65537～2^33−1 之间。原报错把此条件和 RSA 位数、组件长度限制合并成了“RSA 2048～4096 位”，导致有效的 4096 位长度被错误描述。

## 本次已实施的诊断修复

- 区分模数位数、公有指数、私钥组件和文件资源限制。公有指数错误明确说明 4096 位长度本身受支持，改文件头或转换容器不能解决指数限制。
- 保持原有指数范围、签名后端、RSA/SHA-2 策略及秘密处理方式，不放宽认证准入。
- 独立生成两把一次性 RSA 4096 测试密钥：e=65537 用于成功导入和加密 OpenSSH 导出；e=35 用于复现并验证精确拒绝。凭据库测试同时覆盖成功、拒绝不提交及原文件不变。
- 未读取用户私钥或密码；仅读取用户提供的公钥，未复制该公钥到测试夹具。

## 待用户批准的兼容提案

自动审批拒绝了新增 Windows CNG 私钥签名后端并普遍放宽低公有指数的补丁，认为其属于高影响认证密码学变更，需要收窄范围及补充验证。被拒绝的补丁未写入产品代码。

建议收窄为：**仅在 Windows、仅针对 e=35 的既有 RSA 密钥使用 CNG 兼容路径**。e≥65537 的现有 ring 路径不变；其他原来不支持的指数继续拒绝；不生成 e=35 新密钥。非 Windows 暂时明确提示不支持该兼容路径。

该方案仍须满足：

1. RSA 2048～4096 位、完整双素数结构和既有输入/KDF/并发上限。
2. 使用系统 BCrypt RSAFULLPRIVATEBLOB 导入明确的来源参数，不调用第三方密码提取程序，不持久化系统私钥。
3. 只签 RSA/SHA-256、RSA/SHA-512；不启用 RSA/SHA-1，不改变 SSH 传输算法。
4. 来源私有指数参与 CRT 指数计算；导入后使用随机挑战对两种摘要签名并以声明公钥复核，运行签名仍逐次复核。不得绕过损坏组件、一致性校验或身份绑定。
5. 密钥句柄由 RAII 管理并序列化访问，导入缓冲及时清零，复用现有阻塞工作预算、取消和一次性认证签名器。
6. 批准后补齐原生 API、损坏参数、身份/摘要/重复签名拒绝及真实 SSH 认证回归，再构建与评审。独立接口探测成功不等于产品后端已实现。

## 独立可行性验证

使用 Python cryptography/OpenSSL 创建专用 4096 位、e=35 密钥，以独立 TripleDES 实现编码为传统加密 PEM。使用 .NET/CNG 导入对应完整 RSA BLOB，SHA-256 与 SHA-512 签名、公钥验证、修改消息拒绝均通过，签名长度为 512 字节。该探测使用测试私钥，不使用用户私钥，不改变产品的签名后端。
