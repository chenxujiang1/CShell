# ADR-0091：拖放即传、实时暂停与目录导航

- 日期：2026-10-16

拖动文件到另一侧列表后立即入队并启动，不再要求点击开始或勾选确认。
新协议 QueueEnqueueAndStart 在同一次受版本校验的操作中追加文件、保存
队列并启动运行器；已有运行器继续接收新文件。GUI 在提交过程中仍能接收
下一批拖放，等待前一批回执后提交。用户主动暂停整队列时，新文件只入队
等待继续。结果不确定的写入不自动重放；仅明确在写入前拒绝的版本冲突
允许重新读取版本并有限重试。原有队列读写 CAS 校验和回执身份核对保留。

旧暂停只停止派发，单文件暂停通过取消模拟，且依赖已生成的续传检查点。
现在 TransferControl 保留并挂起同一个异步传输 future，暂停时不丢弃
尚未完成的 I/O。继续唤醒原任务，取消也能唤醒暂停中的任务。初始化、
计算内容及实际复制均可暂停。暂停队列在保存派发暂停状态后挂起该 SSH
会话的运行文件，继续队列恢复当前任务和等待项。单文件暂停只作用于指定
会话的 transfer_id。SFTP_LIVE_CONTROL 能力位阻止新 GUI 对旧后台误用。

GUI 先挂起当前写入任务，再读取当前版本并提交队列控制，避免持续进度
检查点令暂停请求反复遇到版本冲突。进度持久化临界区允许完成并释放锁后
再挂起，确保暂停期间的目录刷新、队列读取和继续操作不会被存储锁阻塞。

两侧列表增加“.”和“..”，分别双击刷新当前目录、进入上级；根目录的
上级保持根目录。路径栏旁的下拉框包括祖先、最近访问目录和已加载子目录，
选择即导航。保留可编辑路径和转到按钮。刷新按钮显示中文“刷新”，始终
刷新已加载目录，不采用路径栏中尚未导航的文字。

验证包括指针拖放即时提交、提交期间继续拖入、暂停/继续按钮、目录导航
和小窗口布局；传输 future 的停止与继续、初始化暂停、暂停时取消；本地
SSH/SFTP 服务的上传及下载暂停后进度稳定、继续后的内容一致和会话隔离。

本次需要 GUI 与后台一起更新。只构建到默认 target；试用 bin 中运行文件
退出前保留当前构建，不另存二进制副本，也不主动中断现有后台会话。
