# 按顺序认证与连接时填写账号

SSH 配置第一页合并连接地址、端口、账号和认证方式。保存目标地址时用户名与密码均可留空；密码仍只写入系统凭据存储或 Vault，不进入配置 JSON / SQLite。新配置默认先键盘交互、后密码认证，可勾选私钥、证书、Agent 并用箭头调整顺序。旧配置缺失序列时按原有认证方式解释，编辑后保留等价顺序。

连接先完成主机密钥校验，再按需弹框填写账号密码。通过 SSH none 请求读取服务器支持的方法，未启用的方法跳过。密码认证最多三次；被拒绝时清空本次候选密码并再次提示，取消立即结束。键盘交互沿用多轮验证码及 partial_success 流程，只有明确的普通密码提示可使用保存密码，验证码不保存。

登录弹框提供默认不勾选的“保存账号与密码（认证成功后保存）”。仅在服务器认证成功后写入使用过的候选密码；未提交的可选密码、错误密码、取消和未勾选均不写入。保存前校验配置仍与发起连接时一致，配置被修改或删除时提示并保留新配置。认证成功后的凭据写入验证当前 Vault 世代，不使当前连接因自身保存动作失效；外部锁定仍取消认证。保存账号变更时，使用原有严格绑定读取该配置的便携私钥和口令，再绑定到已验证的账号；不接纳绑定不匹配的凭据，不放宽主机信任。保存失败显示提示，已经通过认证的连接可继续使用。

认证后的实际账号从 transport 返回，写入本次会话的身份及恢复计划。主机密钥、指纹、路由和账号的严格比对继续生效。临时账号不勾选保存时仅存在于当前连接内存。

临时登录沿用已认证 Vault IPC，一次性挑战新增账号、编辑权限、重试状态和保存选项，协议 minor 62。桌面轮询保存后的配置版本以刷新列表。后台在没有桌面响应者时快速返回需要交互，不让无桌面的命令等待两分钟；桌面消失、取消、会话关闭与 Vault 失效均清理待处理挑战。

数据库升级为版本 17，以事务重建 SSH 目标表，允许空用户名并保留现有列与外键约束。沿用原有迁移前备份机制，升级完成做 quick_check。迁移回归使用临时版本 16 数据库，校验旧配置、外键和备份。

OpenSSH 导出保留密码与键盘交互的顺序；不能准确表达的混合认证组合或空账号明确拒绝该格式导出，可用完整 CShell 配置导出保留设置。凭据包按实际启用的方法包含对应种类。
