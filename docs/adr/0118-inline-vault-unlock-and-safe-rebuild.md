# 0118：凭据库同页解锁与安全重建

“密钥对”页面直接展示保护方式、锁定状态、存储位置，以及相应的创建或解锁表单。首次创建可明确选择主密码或系统钥匙串，主密码与私钥口令的区别在表单内说明。解锁后原页立即显示密钥管理，不要求往返设置页。连接凭据模式与主密码更换保留在第二页。

忘记主密码、系统根密钥丢失、库文件损坏或活动库信息缺失时，提供“无法解锁？重建凭据库…”。重建先说明新库为空、旧凭据不能凭空恢复，再选择新保护方式；必须勾选知情确认才能提交。取消或关闭窗口清空临时密码与确认。系统钥匙串访问拒绝/暂时不可用与根密钥不存在使用不同错误状态，先提示检查登录与权限，不自动重建。

## 数据切换

- IPC minor 68 增加 RebuildPassword / RebuildSystem、显式 confirm_rebuild 和公开 storage_path；客户端在旧后台上拒绝重建。
- 旧的主库、系统根密钥引用及已保存的系统根密钥保持原样。新库在同一 credentials 目录下独立的受保护 `vault-*` 子目录准备；新系统模式使用全新根密钥标识，主密码模式独立派生密钥。
- 准备完成后，原子替换 `master.vault.active` 指针选择新库。`master.vault.active.enabled` 标记说明已开始使用代次切换；指针丢失时进入待恢复状态，禁止自动重新启用保留的旧库。
- 旧库不删除、不覆盖，不自动合并。失败的准备目录可能保留用于诊断，不能当作可再生成构建产物清理。备份/迁移应保留整个 credentials 目录；系统保护模式仍依赖相应系统钥匙串。旧版程序不识别活动代次，不应降级后操作此数据目录。
- 跨代次保持固定的控制器文件锁，另一个后台不能通过重建绕过活动库的独占。操作需要当前修订、锁定代次、可用系统桌面和显式确认；已解锁时拒绝重建，先由用户锁定。
- 长时间派生在提交门外完成；最终发布再次检查代次和修订。发布结果不确定时保持锁定，明确要求重新加载，不自动重放重建。重新启动只读取已发布的新库，保持锁定。
- 新库通过独立 VaultSettings 加密记录默认要求 Vault 凭据，避免丢失原模式记录后静默回退到旧系统密码或旧私钥文件；用户仍可明确选择连接的系统存储模式。Profile ID 与全局设置记录隔离，互不覆盖。

重建不会编辑 SSH 配置、服务器 authorized_keys、已导出的密钥或现有会话。已有的连接配置需要重新填写密码或导入私钥；没有原解锁材料时，保留旧库并不等于能恢复其内容。本次开发和验证不重建用户的实际凭据库。

## 验证

界面覆盖同页创建/解锁两种保护模式、确认前禁用重建、请求携带修订和代次、取消不发请求与清空秘密、小窗口实际字体布局。后台覆盖丢失主密码或系统根密钥后创建新库、旧文件字节不变、重启读取新库、系统权限故障与密钥丢失区分、发布失败/结果不确定恢复、独占锁、陈旧请求拒绝、指针路径逃逸拒绝、指针丢失不启用旧库，以及全局模式不被 Profile 覆盖。
