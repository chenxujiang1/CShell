# 向下滚动的分页留白与实时尾部恢复

日期：2026-11-12。分支：`develop/1.1`。固定验证报告：`artifacts/ui-refresh-20261015/logs/scroll-gap-verification.md`。

## 原因

历史页面后面还有数据时，向下滚动允许视口顶部到达页面末行，而不是“最后一个完整屏幕”的顶部。下一页尚未返回或重排时，剩余几行以下没有可画内容，形成非真实的底部空白。预取只按半屏范围触发，也晚于完整视口越过页面的时机。

连续滚动在分页等待期间可能覆盖已有的待滚动距离；固定大小的下一页请求也没有计入该距离。即使异步重排最终已经滚到真实尾部，桌面也只在同步滚轮事件中检查是否返回实时终端，导致历史视图仍保留，需再滚一次才退出。

## 调整

- 页面后面还有数据时，将可见位置限制到最后一个完整屏幕，待下一页和对应重排可用后，再应用累计距离。
- 正反方向的滚轮输入合并到同一个待滚动距离；翻页请求包含目的位置和完整视口所需的行，仍遵守原有行数、文本和内存上限。
- 底部预取覆盖完整视口。窗口增高或换行宽度变化时，已有页面暂时不能覆盖原锚点下方的全部屏幕，则显示完整的已加载内容，并保留逻辑锚点供新页面恢复。
- 异步到达尾部后，当前标签及后台标签都恢复实时终端；正在选择或已冻结的复制内容继续保留。没有实时快照时不清空历史画面。

不以复制旧行、插入伪造内容或裁剪真实服务器输出来填补空白；不改变 SSH 会话、配置、凭据或存储格式。

## 验证边界

保存修复前分页留白、预取与请求范围的失败回归，以及当前／后台标签异步到达尾部仍停留历史视图的失败回归。新增测试覆盖连续滚动、反向抵消、向上滚动保持、长行换行、窗口增高、冻结选区和无实时快照。

原生多窗口门禁以前只拒绝零顶点画面；现在还检查有后续数据时，已加载的充足行数是否填满整个视口，并有专门测试确认它会拒绝“非空但底部缺行”的帧。原生验证仍使用隔离的合成日志，不连接用户服务器。

完整结果由固定报告和源码指纹清单记录。试用程序仅更新 `artifacts/ui-refresh-20261015/bin` 中现有一套；运行中的程序不覆盖、不强退。本轮不提交、不推送、不发布 Release。
