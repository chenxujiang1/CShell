# 终端中文输入法拥有者与预编辑

日期：2026-11-13。分支：`develop/1.1`。固定结果报告：`artifacts/ui-refresh-20261015/logs/terminal-ime-verification.md`。

## 发现

用户反馈连接 Linux 后的终端正文无法输入中文。客户端只处理 IME Commit，忽略 Preedit；Windows winit 明确隐藏系统默认组合文字，因此应用必须自行显示。终端没有组合输入状态，也不能阻止选词确认键或其抬起事件进入远程键盘协议。

输入法开关原先由 egui 平台输出和终端渲染分开管理。终端绕过 egui 再次开启窗口 IME，造成原生状态与 egui 的 allow_ime 缓存不一致；Windows winit 的 set_ime_allowed 会直接调用 ImmAssociateContextEx，没有对重复开启去抖。候选框定位又使用视口尺寸除以快照行列数，和真实字体格宽、高不一致，并额外下移一行。

这些是可确认的客户端接入缺陷；未读取用户服务器配置或将问题唯一归因于某一服务器环境。

## 调整

- 通过同一份 egui PlatformOutput.ime 管理终端和编辑框的原生 IME 开关及位置，不在渲染路径重复直接开启窗口输入法。显式关闭时同步更新 egui 缓存。
- 终端本地显示带下划线的 Preedit；仅确认后的 Commit 经既有终端提交、同步输入及 IPC 入口发送，保持 UTF-8 Text 语义。编辑框继续使用其原有 IME 事件和密码用途。
- 组合期间过滤选词按键，并过滤其后续释放事件；Windows Process 按键在首个预编辑事件之前也会被识别。保留 Ctrl+Break 应急中断。
- 以标签、会话和连接代次区分目标。失焦、切换目标或打开模态时清除预编辑并隔离迟到的提交；包括 winit 在 Commit 前先发空 Preedit 的顺序。
- 候选框使用实际字体格尺寸、当前分屏位置及 DPI；预编辑仅在内存中保存最多 4096 字节，按 UTF-8 边界截断展示，失焦后清除，不记录输入内容。

## 验证与限制

专项回归覆盖持续重绘下的 IME 平台输出、编辑框兼容、中文／emoji UTF-8、确认键隔离、跨会话／连接代次提交隔离、取消输入、字节边界、DPI 位置及预编辑实际生成绘制形状。

Windows 原生隐形窗口测试复现旧的 allow_ime 缓存漂移，并验证新的平台输出在连续二十次更新中保持 IME 开启。事件中的中文是测试构造的，不能当成真人使用微软拼音候选词的人工验收。

真实 Windows PTY 测试把新状态机产生的中文 Commit 经桌面队列、IPC、ConPTY、cmd 和终端解析器往返，确认回显含完整中文。它验证客户端字符通道，不冒充在用户 Linux 服务器执行的测试；未向用户窗口注入按键、未运行用户服务器命令。

完整相关回归、严格静态检查、原生窗口门禁与 Windows 构建结果见固定报告。Mac 实机和真实输入法选词仍需人工验收。试用程序只更新固定 bin，运行中的旧程序不覆盖、不强退；本轮不提交、不推送、不发布。
