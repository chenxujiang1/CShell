# 终端拖拽上传失败项重试

## 使用方式

SFTP 拖拽上传失败后，在上传任务卡点击“重试失败项”。先检查原主机、原目录、已完成数量和待重试数量，再点击“确认重试”。解决同名冲突或权限问题后，可继续原任务；同名文件仍不覆盖。已成功文件保留，前面已完成的批次不重新上传。确认区放在卡片顶部，适配小窗口。

失败原因不明时可以刷新状态。通信超时不会自动再次提交重试；确认请求绑定原任务的一次版本，重复确认和过期确认被拒绝。重试处理中不能移除任务记录，须等待后台回执。

## 固定边界

- 重试使用原文件清单、原目标目录、原校验策略和原已认证 SSH 连接代次；不重新扫描文件夹，不追随之后的 `cd`，不迁移到其他标签或重连后的新会话。
- 原连接失效时，先重新连接、核对远端文件，再选择待上传文件。程序不重新索取 MFA 来自动重放旧任务。
- 保留当前批次的持久化队列，沿用逐文件校验恢复。已成功项不重复入队；只有尚未调度的文件和队列确认可恢复的失败项进入重试。远端发布结果不确定、需要清理或仍在运行的项阻止整批重试，提示核对远端。
- 失败后暂停调度，停止本批活动文件并等待回执结算；关闭上传子消费者，原交互终端继续使用。重试时重新借用原传输的子消费者，不重新认证。
- 最多同时四个上传任务。后台最多保留八份重试清单，每份文件计划最多 4 MiB，确认有效期十分钟；容量不足时释放较早的清单。任务记录被回收、程序重启或清单失效后，须核对远端再重新选择文件。释放清单不会删除本地、远端文件或已有恢复日志。
- ZMODEM 不能可靠确认逐文件发布结果，不提供直接重试；核对远端后改用 SFTP 选择未完成文件。

协议 minor 82 新增只读检查与显式确认操作，原上传快照结构保持兼容。旧后台会在发送重试前被客户端版本检查拦截。

## 回归

使用隔离的本机 SSH/SFTP 服务验证跨批次成功项保留、冲突解除后恢复、固定目录、固定文件清单、重复确认、跨会话拒绝、源连接退出及无需再次 MFA。界面回归实际点击确认按钮，并验证请求版本、处理中禁止重复提交和移除、目标不匹配拒绝、重试后清除完成计时。队列状态回归阻止发布不确定、仍在运行、需清理及取消项。

## 同轮缺陷修复

Windows 本地 ConPTY 子进程会继承启动器的“忽略 Ctrl+C”属性。创建 PTY 前调用 `SetConsoleCtrlHandler(NULL, FALSE)` 恢复正常继承，不发送信号、不移除已注册处理器；隔离子进程回归先制造该属性，再确认真实 `ping -t` 可中断且 shell 可继续输入。

安全依赖升级至 russh 0.65.1、libsqlite3-sys 0.39.1。SQLx 0.9.0 发布版的 SQLite 版本上限阻止安全升级，因此仅在带许可证的 `vendor/sqlx-sqlite` 调整依赖范围，维护说明见该目录 `CSHELL-PATCH.md`；不增加安全公告例外。数据库迁移和配置保留沿用原工作区回归。

原上传集成测试共用八秒等待本地配置准备、建立 TCP 和 MFA，导致 TCP 尚未连接就被误报为 MFA 超时。夹具按现有传输连接预算给连接准备三十秒，接收本次新 TCP 后单独限制八秒等待 MFA；轮询不延长预算，已存在的 TCP 连接不触发新阶段，逾期准备也不能切换阶段绕过超时。提前失败会立即报告，并保留非敏感阶段计数。产品连接、认证策略及认证超时没有修改。
