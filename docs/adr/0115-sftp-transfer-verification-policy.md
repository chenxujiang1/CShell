# SFTP 传输校验策略与恢复检查点

新建传输默认使用标准模式：逐请求确认写入、完成时强制落盘、核对文件大小，以独占创建的临时文件和原有 no-replace 硬链接发布流程保护目标。不再为了正常完成传输而反复读回整个远端文件。标准模式不声称目标磁盘内容已通过完整 SHA-256 核对。

完整模式在传输源数据时计算本地 SHA-256，目标必须与该摘要一致。上传优先使用服务器明确声明的 check-file-handle 扩展（包括 supported2 的 check-file 声明）；这是可选草案扩展，不假设 OpenSSH 支持它。否则通过现有已认证 SSH 连接的独立非 PTY 渠道运行只读 sha256sum，不向终端注入命令，不再次认证。

调用命令前，先在 Create 意图覆盖的独占临时文件中写入随机短挑战，要求 SSH 渠道读回完全相同的内容，再截断至零并核对大小，然后才写入用户文件。这验证了 SFTP 与 exec 的文件命名空间映射，不仅比较路径文本。没有创建额外探测文件。无法验证映射、exec 被禁用、工具不可用、回复格式不合法或扩展不可用时，完整模式只执行一次 SFTP 全量读回。已经收到的合法摘要不匹配时直接失败，不改用标准模式或通过重试摘要掩盖错误。完整下载只从远端读取一次，传输中计算源摘要，并在本地验证落盘文件。

命令路径使用 POSIX 单引号转义，拒绝控制字符和非绝对路径；输出最多 1024 字节，要求退出码为零以及精确的摘要格式。命名空间探测最多 3 秒，服务器摘要最多 30 分钟；取消、超时、失败均释放独立渠道而不关闭共享 SSH 连接。服务器计算摘要时显示“服务器校验 / 服务器计算 SHA-256…”，不伪造可知的百分比。

全局默认存储在已有 transfer-settings.json，兼容原有 ZMODEM 下载目录；SSH 配置可以选择继承全局、标准或完整。继承值在新任务加入队列时解析并固定为该任务策略。修改全局或会话设置不改变已加入的任务。完成状态区分“已传输”和“已校验”。涉及已存在目标的比较、备份替换和编辑保存继续使用原严格核对流程，并在界面说明；本次不降低这些冲突保护。

网络批次保持 1 MiB、每批最多 16 个 32 KiB 请求，文件并发保持 3。新模式先持久化一个最多 16 MiB 的写入范围，再发送有界批次；达到范围末尾、传输完成或一个批次完成时已过约 2 秒，先 fsync 再保存已确认字节和前缀摘要。每个检查点只有写入意图和完成事实两次原子队列保存。网络很慢时，2 秒是批次间检查时机，不是硬实时落盘承诺。最后阶段额外强制落盘，不将仍未落盘的数据记录为可直接信任的恢复事实。

取消或崩溃后，磁盘日志保留检查点起点和最大写入终点。恢复前重新冻结当前完整源摘要，检查已保存前缀 SHA-256，逐字节比较临时文件与源，包括未确认范围，确认目标仍不存在，再继续。尚未完成流式摘要的 content 使用显式 digest_pending 标记，不能进入验证完成或发布状态；完成后替换为实际摘要。创建或发布结果不确定时不自动重放，沿用显式恢复和清理。恢复、发布收养及异常清理仍执行完整内容核对。

IPC minor 65 增加会话设置字段和服务器摘要阶段。队列 draft.verification 缺失时保留原严格算法；digest_pending 为 false 时不输出新字段，旧文档的编码和校验摘要保持兼容。新增策略只影响显式选择新模式的任务；不迁移或静默降低历史任务的校验要求。旧后台不支持新策略时，GUI 提示一起更新。

协议依据：[SFTP 文件摘要可选扩展草案](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-extensions-00#section-3)、[supported2 格式](https://www.ietf.org/archive/id/draft-ietf-secsh-filexfer-13.txt)、[OpenSSH 扩展说明](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL)。
