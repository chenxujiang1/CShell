# CShell 1.1.0-dev.1 开发版

软件版本：`1.1.0-dev.1`。构建编号：`11001`。开发分支：`develop/1.1`。

这是 1.1 的开发试用版本，不是正式版。可分发的程序以同一源码提交的完整 CI 结果为准；本文存在不表示 CI、Mac 构建或发布已经完成。自动化结果与实机兼容性分别记录，未执行的验收项目不计为通过。

## 本轮功能

- 服务器资源：工具栏直接打开 Linux 基础资源面板；默认采集一次，自动刷新默认关闭、间隔为 `0`。采样复用认证连接，不安装常驻 Agent、不保存监控历史。磁盘排行、全量进程和趋势图不在当前基础面板范围。
- 跳板：由 CShell 创建受管理的 B 会话，支持通过 A 上的密钥免密认证及可选复用已认证跳板。终端、SFTP 和资源采集绑定实际会话；在 A 的终端里手工执行 `ssh B` 不会自动改变上传或采集目标。
- 上传：终端拖放 SFTP 任务支持暂停、取消、结束后移除和失败项重试。先检查原主机、原目录及数量，再确认重试；保留成功项和原文件清单，同名文件不覆盖。
- 终端：完善 Ctrl+C、中文输入、双击分词、三击逻辑行、全选、持续输出回看、分页与选区稳定性；快捷键说明位于“帮助”下，与“关于 CShell”同级。
- 连接与布局：诊断按需展开、侧栏完整收起、恢复之前的输入焦点，断线后输入可进入恢复连接流程；旧命令不会自动重放到新 shell。
- 依赖：升级 SSH 和 SQLite 安全依赖，保留原 cargo deny 策略。SQLx SQLite 的局部依赖范围补丁有来源、许可证及移除说明。

## 明确限制

- 失败项直接重试只适用于原 SSH 连接及连接代次仍有效、并有安全恢复依据的 SFTP 任务。清单最多保留八份，确认有效期十分钟；过期、重启或原连接失效后，核对远端再重新选择文件。
- 发布结果不确定、需要清理的传输，以及 ZMODEM 失败，不会盲目重传。取消不撤销已经完成的文件。
- 资源面板以常见 Linux 的只读基础指标为范围；权限、系统和容器环境可能影响指标口径，缺失数据按未知显示。
- Mac 包仍为 ad-hoc 签名，没有 Developer ID 签名和 Apple 公证。不同系统与实机兼容性没有因 CI 通过而自动获得认证。
- 独立实时日志工作台、断线后绑定新连接恢复旧上传、远程搜索、Docker 管理及自动更新均不作为本轮新增功能开发。

## 获取与核对程序

1. 提交经维护者确认的源码到 `develop/1.1`，查看该提交的完整 `ci` 工作流；全部前置门禁通过后才产生试用包。推送和发布均由维护者确认，工作流不自动创建 Release。
2. 从 Artifacts 下载 Windows x64、Mac arm64 或 Mac x64；解压外层 artifact，取出程序 ZIP 与对应 `.sha256`。包名沿用固定名称，不能混用不同提交的三个平台附件。
3. 校验程序 ZIP 的 SHA-256；包内 `README-first-run.txt` 和 `build-info.json` 应为 `1.1.0-dev.1`、构建 `11001`。源码提交与对应 CI 一致，`source_dirty` 为 `false`，三个程序的哈希和版本一致。
4. 正常退出旧 GUI 与相关后台后，一并替换 Windows 的三个程序或整个 Mac app；保留用户数据。目录、旧试用布局和备份说明见 [TRIAL.md](../../TRIAL.md#升级与配置保留)。不通过删除数据库或凭据库解决升级问题。

## 版本元数据

| 位置 | 本版值 |
| --- | --- |
| Cargo、关于页面、三个程序的 `--version` | `1.1.0-dev.1` |
| Windows 字符串版本 | `1.1.0-dev.1` |
| Windows 数值版本、预发布标志 | `1.1.0.11001`、启用 |
| Mac `CFBundleShortVersionString` | `1.1.0` |
| Mac `CFBundleVersion` | `11001` |

完整软件版本和数字构建编号均保留。Mac 数字字段遵循 [Apple 当前版本字段说明](https://developer.apple.com/documentation/bundleresources/information-property-list/cfbundleversion)及[短版本说明](https://developer.apple.com/documentation/bundleresources/information-property-list/cfbundleshortversionstring)，Windows 预发布标志遵循 [Microsoft VERSIONINFO 说明](https://learn.microsoft.com/en-us/windows/win32/menurc/versioninfo-resource)。后续分发时递增构建编号，不复用同一版号冒充不同源码。

## 手动发布

如维护者决定将此开发版发布为 Release，先固定通过完整 CI 的提交，再从该提交建立 `v1.1.0-dev.1` 标签，使用标题 `CShell 1.1.0-dev.1` 并勾选 pre-release。上传三个程序 ZIP 与三个 `.sha256` 文件，核对无误后由维护者点击发布。不要移动 `v1.0.0`，也不要将开发版合并成 1.0 维护版本。
