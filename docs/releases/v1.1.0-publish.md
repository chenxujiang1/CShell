# CShell 1.1.0 手动发布

本文件供维护者操作。版本为 `1.1.0`，构建编号 `11002`。候选在 `develop/1.1` 上验证。此文档不表示 CI 已通过、标签已创建或 Release 已发布。

1. **固定源码。** 打开 [CI 工作流](https://github.com/chenxujiang1/CShell/actions/workflows/ci.yml)，找到候选提交对应的成功运行。全部前置检查和三个原生打包任务通过后，记录完整提交 SHA。在决定正式发布前，确认是否接受 [Mac 签名限制](v1.1.0.md#已知限制)；若补签名和公证，应核对最终签名后的构建和哈希。
2. **下载附件。** 从同一次 CI 的 Artifacts 下载下表三包。解压外层 artifact，取出里面的三个程序 ZIP 和对应三个 `.zip.sha256`。将旧 `1.1.0-dev.1` 和 `1.0.0` 同名文件留在原归档位置，避免混传。Release 附件不使用外层 artifact ZIP。
3. **校验。** 使用 PowerShell `Get-FileHash -Algorithm SHA256 -LiteralPath <程序 ZIP>` 或 macOS `shasum -a 256 -c <程序 ZIP.sha256>` 对照校验文件。再查看包内 `build-info.json`：版本为 `1.1.0`、构建 `11002`、`source_dirty` 为 `false`，三个包的 `source_commit` 与该次 CI 完全一致。
4. **确定标签和分支。** 确认要正式发布后，由维护者在该完整 SHA 上建立固定标签 `v1.1.0`。如需更新 `main`，应与已验证的候选保持一致；已有不同提交时先复核。不要移动 `v1.0.0`，也不要从已经前进的分支临时建立标签。
5. **保存并核对 Release 草稿。** 在 [GitHub 新建 Release](https://github.com/chenxujiang1/CShell/releases/new) 选择 `v1.1.0`，标题填 `CShell 1.1.0`，正文使用[发布说明](v1.1.0.md)。上传六个附件，核对标签、限制说明和所有文件。正式发布时不勾选 pre-release；如果仍用于公开试用，应当明确标为预发布。[GitHub 官方操作说明](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)
6. **由维护者发布。** 确认草稿后点击 Publish release。请从公开页面重新下载一个附件并核对校验值，确认用户获取的是指定提交的程序。
